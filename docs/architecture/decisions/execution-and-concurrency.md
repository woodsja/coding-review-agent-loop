# Execution and concurrency — decisions

Decision log for [Execution and concurrency](../execution-and-concurrency.md). Entries are append-only: a
replaced entry gets a `Superseded by #M: <clause>.` note appended and is
never rewritten or deleted. The detail doc describes the current design.

- Concurrent default-dir invocations on one repository are supported by giving each run its own detached worktree over one shared store per repository and agent (#1162).
- `agent-loop transport-check` runs one production fetch with the operator's credentials and is required before merging transport changes (#1383).
- SSH transport honours a non-executing subset of `~/.ssh/config` for the literal URL host, refusing rather than escaping any unsafe value, and never runs `ssh -G` (#1380).
- Same-UID live races against `~/.ssh` are left out of scope for the SSH transport (#1371).
- Antigravity tracks quota exhaustion per quota group for the logical run, so a verified exhaustion skips the whole group with no retry instead of retrying each model (#1236).
- The Antigravity `semantic-dedupe` turn reuses the isolated `repair` path (sibling GEMINI lock, no checkout snapshot, strict empty allowlist) with a stdout-only classification contract, so a classifier never creates git metadata in its temporary directory or reads a stale response file (#1472).
- The fork's checkpoint 4A local editor handoff starts as an unwired Git-only primitive: host-owned expected trees and direct raw-object verification remain separate from disposable operator objects/indexes; ignore-rule edits and unsupported inputs fail closed until broader integration is tested (#1).
- The fork's partial checkpoint 4C permits explicitly attested native local Claude executables via descriptor-bound read-only mounts and digest/inode checks before and after execution. Explicit session-file authentication uses an O_PATH descriptor and a read-only mount into disposable CLAUDE_CONFIG_DIR; host Python never reads session contents. Host settings and install/login parent directories remain unmounted. Actual CLI subscription compatibility requires an owner-run disposable smoke test. Issue/PR workflow integration and durable recovery remain outstanding (#1).
- The fork's checkpoint 4D reuses the issue-loop validated turn and review/handoff contracts around one small `SplitIssueHandoff` adapter, freezing only an explicit versioned editor new-file declaration, authenticating evidence before publication and synchronizing only the verified commit (#1). Superseded by #1: durable phases, PR corrections and recovery are implemented.
- Trusted handoff metadata and the phase journal live in a private per-user state directory outside every root a Codex workspace-write editor can modify, never under `/tmp`, and are sealed against editor tampering; OS denial is proven against the real `codex sandbox` (#1).
- Split-role recovery journals each phase (`EDITED`, `COMMITTED`, `PUSHED`, `PR_BOUND`) and restarts by restoring the frozen candidate from hash-verified loose objects, re-deriving the deterministic commit and relying on idempotent push and PR binding, instead of persisting model sessions or inventing a second publication path (#1).
- The public `--git-operator claude` gate stays closed after the direct issue, correction, recovery and permission tests pass, until the required independent review of the branch is complete (#1). Superseded by #1: the CLI runs direct issue and ordinary pr through the claimed workflow once the pre-claim entry gate passes; the live Claude proof remains a separate host smoke gate.
- The `--git-operator claude` entry gate runs before worktree claims and refuses dry-run, missing or unverifiable owner CLI digest or session, and unsupported flows; the handoff refuses required-signature rulesets or protection, or an unverifiable policy, before any editor turn, because operator commits are unsigned (#1).
- Split-role publication keeps the credential-bearing host push store in the private handoff state root outside every editor-writable location, and pins a Codex editor's writable roots by ignoring inherited user rules and writable-root configuration. Changes to operator-masked project credential/settings paths are rejected before launching the Git operator rather than producing a late tree mismatch (#1).
- The split-role Codex editor explicitly ignores inherited user configuration/rules, clears the permission profile and writable roots, and validates production CLI flags and adversarial user/project settings against a real sandbox. Rendered recovery commands discard Claude operator attestation and session paths; resumption must be reauthorized instead of publishing private session locations (#1).
